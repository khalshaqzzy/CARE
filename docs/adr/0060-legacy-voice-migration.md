# ADR-0060: Migrating closed Voices from earlier member-voice platforms

- Status: Accepted (implemented on a branch, not released)
- Date: 5 October 2026
- Related: ADR-0029, ADR-0054, ADR-0059

## Context

CARE replaces the member-voice platforms already in use. Management wants the Voices people sent there to be visible in CARE, especially in the dashboard. The old platforms have no chat, and some have no rating or priority. CARE had no way to import Voices: every Voice was created through the submit flow, which needs a draft, an AI classification, a route, and an active reporter account.

## Decision

- **Only closed Voices are migrated.** Voices still in progress are finished on the old platform. They come over in a later batch once closed. Batches repeat during the transition period only.
- **Input is one workbook per batch.** PICs of the old platforms fill `docs/migration/Template_Migrasi_Voice_CARE.xlsx`. The workbook is generated by `docs/migration/build_template.py`. The CARE team fills Area, Category, and Severity, judging Severity from the Voice text. Severity is never defaulted.
- **A developer runs the import as a one-off CLI.** There is no upload UI. `import-legacy-voices` (`apps/api/src/cli`) reads the workbook. A dry run writes a per-row report (`<file>-hasil.csv`). `--commit` writes every row in one serializable transaction: if any row has an error, nothing is written.
- **The old ID is the identity.** `Voice.legacySource` (the platform) and `Voice.legacyId` are unique together. A pair already in CARE is reported as skipped, so a later batch may repeat rows. Migrated data is final; corrections are made separately.
- **Migrated Voices look like closed CARE Voices.** They are created with:
  - a display ID `MIG-<YYYYMM of submit>-<sequence>`, separate from the `CARE-` sequence;
  - status Closed;
  - one closure cycle that is already accepted;
  - SUBMITTED, RESPONDED, CLOSED, and RATED events at their historical times, so dashboard averages use the old timestamps;
  - the rating, when one exists.

  An empty response date or rating is left empty and excluded from averages. It is never recorded as zero.

- **Organization:**
  - The handling department of a General Voice must match a current CARE department, because the default dashboard groups by it. The importer stores CARE's own names, with `handlingOrganizationSource = 'LEGACY_IMPORT'`.
  - The reporter's department is matched when it still exists. Otherwise it is kept as written.
- **People are matched by NoReg.** Reporters and PICs missing from CARE become inactive workforce accounts. They get the same initial password the organization import gives, so a later HR file activates them normally.
- **Side effects:**
  - Nothing is notified, classified, or escalated.
  - Private Voices keep the reporter identity hidden from the union, because the old platforms never asked for consent.
  - Migrated Voices cannot be rated in CARE.
  - Voice search also matches the old ID.

## Consequences

- The operations dashboard counts every migrated Voice as on time, because the old platforms recorded no deadlines. Timeliness is meaningful only for Voices submitted in CARE.
- Organization names that have changed must be rewritten to the current CARE names before import. The dry-run report lists every row that does not match.
- The CLI runs inside the API image on the server (see `docs/migration/README.md`). It needs no new compose service.
